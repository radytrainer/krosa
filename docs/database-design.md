# Database Design (PostgreSQL)

Conventions:

- Primary keys: `uuid` (generated by the application via Prisma `@default(uuid())`; v7 where supported).
- Tables/columns `snake_case` (Prisma models mapped with `@@map`/`@map`).
- All timestamps `timestamptz` in UTC: `created_at`, `updated_at`.
- Grading values `numeric`: marks/max marks `numeric(8,3)`, weights `numeric(6,3)`, credits `numeric(4,1)`.
- Foreign keys default to `ON DELETE RESTRICT`. Academic records are archived, never cascaded away.
  Exceptions are noted (`CASCADE` only for pure child rows such as scheme items of a deleted draft).
- Constraints that Prisma cannot express (CHECKs, partial unique indexes) are added in raw SQL in the
  migration files and listed below.

## 1. Entity relationships

```
generations 1─5 terms 1─* course_offerings *─1 courses
generations 1─* google_sheet_sources 1─* course_offerings (owner source)
generations 1─* students 1─1 users (role=STUDENT)
course_offerings 1─* assessment_criteria
course_offerings 1─* grading_schemes 1─* grading_scheme_items *─1 assessment_criteria
students *─* course_offerings  via enrollments
enrollments 1─* assessment_scores *─1 assessment_criteria
assessment_scores 1─* assessment_score_revisions
users 1─* auth_sessions 1─* refresh_tokens
sync_jobs (parent) 1─* sync_jobs (children) ; sync_jobs 1─* sync_errors ; sync_jobs *─1 google_sheet_sources
audit_logs *─1 users (actor, nullable)
```

**Missing mark** = no row. A blank cell that previously had a value is not auto-deleted
(policy: "never delete on disappearance"); the job reports `MARK_CLEARED_IN_SOURCE` as a warning and
the admin decides. This prevents an accidental clear in the sheet from erasing a recorded mark.

## 3. Implementation notes (Phase 2)

- **Prisma 7.10** with preview features `partialIndexes` and `postgresqlExtensions`: citext, pg_trgm,
  the trigram index and all partial unique indexes are declared in `schema.prisma`. Only CHECK
  constraints and triggers are hand-written SQL at the end of the init migration. Prisma doesn't
  manage either, so neither shows up as drift (`prisma migrate diff` is empty after deploy).
- **Primary keys** are UUIDv7 (`@default(uuid(7))`): time-ordered, so inserts stay index-friendly.
- **Same-offering integrity** is enforced by composite foreign keys, not application code:
  `assessment_scores` and `grading_scheme_items` carry a denormalized `offering_id`, and
  `(enrollment_id, offering_id)`, `(criterion_id, offering_id)` and `(scheme_id, offering_id)`
  reference matching composite UNIQUE keys. A score can never point at a criterion from another
  course, even through a buggy code path.
- **Triggers**
  - `grading_schemes_guard`: allows only DRAFT→PUBLISHED→ARCHIVED, makes offering and version
    immutable, allows deleting drafts only, and freezes `total_weight` once published.
  - `grading_scheme_items_guard`: rejects INSERT/UPDATE/DELETE of items unless the scheme is a DRAFT.
  - `audit_logs_append_only` and `assessment_score_revisions_append_only`: reject UPDATE and
    DELETE. A retention job may purge only after `SET LOCAL ssrs.allow_append_only_purge = 'on'`
    inside its transaction.
- **Optional foreign keys** (`source_id`, `published_by`…) use `ON DELETE SET NULL`. Users, sources and
  academic records are never deleted by the application; they are disabled or archived.
- Constraint behaviour is covered by `packages/database/test/constraints.integration-spec.ts`.

## 4. Key design decisions

1. **Dynamic criteria are rows.** Adding "Quiz 4" inserts a criterion and a new draft scheme item.
   No DDL, no JSON blobs of marks.
2. **Versioned schemes hold max mark and weight.** Changing either creates a new version; old
   versions stay ARCHIVED for audit. Results always use the PUBLISHED version.
3. **Rename-safe.** Scores reference `criterion_id`; the sheet references `key`. Display names are
   free to change.
4. **Mark validation** against the max mark of the PUBLISHED scheme, or against the scheme being
   created in the same sync if none is published. If a draft raises a max mark, marks above the
   current published max are rejected until the draft is published (the job error tells the admin
   why).
5. **Calculated values are not stored.** Final scores are derived on read (cheap: a handful of
   criteria per course) and cached. This avoids stale denormalized grades after a scheme change.
6. **No cascading deletes of academic data.** Archive instead.
