# Run Krosa free on one Oracle VM

**Put the whole Docker Compose stack on one Oracle Cloud Always Free Ampere A1 VM (2 OCPU / 12 GB Arm, up to 200 GB disk) in the Singapore home region.** It is the only free offer found that meets the documented 2 vCPU / 4 GB / 40 GB minimum with no time limit. It also runs `docs/deployment.md` almost unchanged: the one real change is building Krosa's images for `linux/arm64`. The backup is an **AWS Free plan account running a t4g.small (2 vCPU / 2 GB Arm) in Singapore**. You can open it straight away, but it gives about 6 months free, and the t4g.small free trial ends on 31 December 2026, which is eight weeks from today. Apply for **DigitalOcean for Nonprofits ($2,500 credit for one year)** at the same time, because it would pay for a standard 2 vCPU / 4 GB droplet for the whole test. If both fall through, the cheapest paid option is **one 2 GB VPS in Singapore for about $12 a month, or a 4 GB one for about $24 a month** (about $144–288 a year). A free PaaS split was also checked: web and API on Northflank or Render, with Neon Postgres and Upstash or Redis Cloud. It is technically possible but not recommended. It needs code and config changes, and it runs into sleeping services, command quotas and inactivity rules. Free tiers also change without notice: Oracle cut its own allowance in half in June 2026 and Koyeb dropped its free plan in 2026. So plan for a possible migration halfway through the 6–12 months, whichever host you pick.

## One VM keeps the deployment guide intact

The deployment guide describes one Linux server with Docker Engine running Caddy, web, API, worker, a one-shot `migrate`, Postgres 17, Redis 7.4 and a nightly `pg_dump` container. Only Caddy publishes ports 80 and 443, and Caddy gets TLS certificates from Let's Encrypt. Any host that offers a plain Linux VM with a public IPv4 address and open ports 80/443 can run that compose file unchanged. A PaaS cannot: the platform takes over routing and TLS, Postgres and Redis have to move to managed services, and the backup container has to become a scheduled job. That is why the comparison below favours VMs.

The documented minimum is set for "a school of a few thousand students", which is well above 50–100 test users. The research team estimates the stack uses **about 0.6–1.0 GB of RAM at low traffic**. This figure comes from typical per-process numbers, not from measuring Krosa. On that basis, a 2 GB VM is workable if the images are built elsewhere. A 1 GB VM (Oracle E2.1.Micro, GCP e2-micro, Azure's free B-series) would depend on swap and caps on Node's heap. It would also slow down during syncs, so 1 GB is fit only for demos. Building the images on the server is the heaviest step, because `next build` usually needs 2 GB or more. Run `docker stats` locally during a sync to replace this estimate with real numbers before you choose a VM size.

## Oracle fits on paper; the risks are sign-up, capacity and idle reclaim

Oracle's current documentation sets the A1 Always Free allowance at **1,500 OCPU-hours and 9,000 GB-hours a month, which equals 2 OCPUs and 12 GB of RAM**. The tenancy also gets 200 GB of combined block storage, 10 TB of outbound traffic a month, and two extra 1 GB AMD micro instances ([Oracle docs](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)). That is three times the documented RAM minimum and five times the disk, on a free tier with no end date.

That allowance used to be 4 OCPU / 24 GB. **Oracle halved it in mid-2026 and announced it only by changing the docs.** Free-only accounts above the new limit had their instances shut down until they were resized. Oracle support emails reportedly said pay-as-you-go accounts keep the old 4 OCPU / 24 GB, but Oracle has not published this ([InfoQ](https://infoq.com/news/2026/07/oracle-cloud-free-tier-limits/); [linuxiac](https://linuxiac.com/oracle-quietly-cuts-free-tier-ampere-a1-resources-in-half/)). The lesson for PNC is not "avoid Oracle". It is "keep backups off the box and be ready to move", because Oracle can change the terms again during the test.

Four practical risks remain.

**Getting the account approved.** Virtual and prepaid cards are almost always rejected, some debit cards fail, and using a VPN raises the rejection rate ([ITNext](https://itnext.io/why-creating-an-oci-free-tier-account-is-so-hard-and-what-you-can-do-instead-7a06b83ec576); [Oracle forums](https://forums.oracle.com/ords/apexds/post/signup-issues-with-oracle-cloud-free-tier-account-7894)). No source confirms whether sign-up works with a Cambodian card, so use an organisational credit card from a major bank and do not use a VPN.

**Capacity.** Free compute must run in the home region, which cannot be changed after sign-up. Oracle documents "out of host capacity" errors when free shapes are temporarily unavailable ([Oracle docs](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)). One user with a Singapore home region reports never being able to create an instance ([LowEndTalk](https://lowendtalk.com/discussion/comment/3711352/)). This is a single anecdote, and there is no data on Singapore capacity in late 2026.

**Idle reclaim.** Oracle can reclaim an A1 instance when, over 7 days, its 95th-percentile CPU, network *and* memory use are all below 20% ([Oracle docs](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)). A quiet test server using under 2.4 GB of 12 GB could meet all three. Memory is the easiest condition to break: give Postgres a larger `shared_buffers` so steady memory use stays above 20%. Upgrading the account to pay-as-you-go is commonly said to stop reclamation, but Oracle's documentation does not confirm this.

**Arm64.** Build the `web`, `api`, `worker` and `migrate` targets for `linux/arm64`. With 12 GB of RAM you can simply build on the VM, as the guide already says. Then check native dependencies such as the Prisma engines on arm64. The official Postgres, Redis, Node and Caddy images are multi-arch, which the research team knew but did not re-verify in this research.

## AWS and DigitalOcean credits cover the gap if Oracle fails

Since July 2025, new AWS accounts start on a credit-based Free plan: **$100 at sign-up plus up to $100 more earned by trying services**. The plan ends after 6 months or when the credits run out, whichever comes first, and the account then closes. Data is kept for 90 days, and unused credits carry over if you upgrade to a paid plan ([AWS Billing docs](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-plans.html); [AWS News Blog](https://aws.amazon.com/blogs/aws/aws-free-tier-update-new-customers-can-get-started-and-explore-aws-with-up-to-200-in-credits)). Separately, **t4g.small is free for 750 hours a month until 31 December 2026** ([AWS T4g](https://aws.amazon.com/ec2/instance-types/t4/)). The sources do not say whether that trial also applies on the Free plan.

The research team estimates a t4g.small in Singapore, with a public IPv4 address and 30–40 GB of gp3 storage, at about $20–25 a month, so $200 would last roughly 8–10 months. They did not check this against AWS's own price pages. In practice this means about six months free on the Free plan. Reaching 12 months means upgrading to the Paid plan with budget alerts and accepting a small bill near the end. The 4 GB `t3.medium` that `docs/deployment.md` §8 specifies would use up the credits much faster. On 2 GB, prebuild the images in CI (multi-arch for Arm) and pull them, instead of running `--build` on the server.

**DigitalOcean for Nonprofits** is the best-fitting credit programme found: **$2,500 of one-time credit that expires one year after you apply**. It is open to the "global equivalents" of US 501(c)(3) charities, and even to unregistered social-impact projects. Eligibility is checked through Percent ([DigitalOcean blog](https://www.digitalocean.com/blog/driving-impact-do-for-nonprofits-social-enterprises); [DigitalOcean nonprofits](https://DigitalOcean.com/impact/nonprofits)). These pages are undated, so confirm the terms are still current for 2026. Unlike the AWS, Microsoft and Google nonprofit programmes, nothing found shows that it excludes schools. Those three exclude educational institutions outright: AWS names "trade schools" ([AWS Nonprofit Credit Program](https://aws.amazon.com/government-education/nonprofits/nonprofit-credit-program/)), Microsoft excludes "formal educational institutions" ([Microsoft Nonprofits eligibility](https://www.microsoft.com/en-us/nonprofits/eligibility)), and Google excludes schools while listing Cambodia as a supported country ([Google for Nonprofits](https://support.google.com/nonprofits/answer/3215869?hl=en)). PNC has a chance only if it applies as the registered NGO rather than as the school, and no source shows how that turns out. The often-quoted DigitalOcean credit in the GitHub Student Pack is no longer listed ([GitHub Education](https://education.github.com/pack)).

If no free route works, the cheapest dependable fallback is a mainstream 2 vCPU / 4 GB VPS in Singapore at **about $24 a month (DigitalOcean lists $28 for its Premium Intel tier)** ([Cloud Mercato](https://pcr.cloud-mercato.com/providers/digitalocean/flavors/s-2vcpu-4gb-intel); [Better Stack](https://betterstack.com/community/guides/web-servers/digitalocean-vs-vultr/)). A 2 GB plan at about $12 a month is likely enough for this test load; that price comes from the research team's general knowledge. Hetzner is usually cheaper, but it raised prices twice in 2026, its cheapest plans could not be ordered as of October 2026, and its Singapore prices are 40–67% higher than in the EU ([bitdoze](https://www.bitdoze.com/hetzner-cloud-cost-optimized-plans); [costgoat](https://costgoat.com/pricing/hetzner)).

## A free PaaS split breaks Krosa's always-on worker

The BullMQ worker is the main obstacle. It has to stay connected to Redis at all times, and most free PaaS tiers either do not allow background workers or put them to sleep. **Render's free tier does not include background workers**, and its free web services spin down after 15 minutes idle, then take about a minute to start again ([Render community](https://community.render.com/t/web-worker-not-part-of-the-free-plan/24555); [Render docs](https://render.com/docs/free)). Render's free Postgres also expires after 30 days, and its free Key Value store loses all data on restart. Koyeb now needs a paid plan for new sign-ups ([Koyeb blog](https://koyeb.com/blog/koyeb-is-joining-mistral-ai-to-build-the-future-of-ai-infrastructure)). Fly.io has no free tier for new organisations ([Fly.io pricing](https://docs.fly.io/about/pricing)). Railway gives only $1 a month after its trial ([Railway docs](https://docs.railway.com/reference/pricing/free-trial)). Vercel Hobby limits use to "non-commercial, personal use only", which rules it out for an organisation ([Vercel Hobby docs](https://vercel.com/docs/plans/hobby)). **Northflank's Sandbox** is the one exception: 2 always-on services with no sleeping and no card needed ([Northflank pricing](https://northflank.com/pricing)). But Krosa runs three Node processes, the per-service resource limits are not published, nothing confirms the free tier can deploy to Singapore, and the pricing page carried a security-incident notice when the research team checked it. Cloud Run and Azure Container Apps give an ongoing monthly free allowance of 180,000 vCPU-seconds ([Google Cloud](https://docs.cloud.google.com/free/docs/free-cloud-features); [Azure ACA](https://azure.microsoft.com/en-us/pricing/details/container-apps/)). That is about 50 vCPU-hours a month, enough only for services that scale to zero, so an always-on worker would cost money there.

The data tier is easier. **Neon Free** offers Singapore, 1 GB per project, no card, and is never paused or deleted for inactivity. But it scales to zero after 5 minutes and gets 100 compute-hours a month, and running out suspends the database until the next month ([Neon pricing](https://neon.com/pricing)). Redis is harder. BullMQ requires `maxmemory-policy noeviction` ([BullMQ docs](https://docs.bullmq.io/guide/going-to-production)). Upstash Free caps usage at 500K commands a month, and Upstash itself recommends a fixed paid plan for BullMQ because the queue polls Redis even when idle ([Upstash BullMQ](https://upstash.com/docs/redis/integrations/bullmq)). The research team estimates an idle worker on default settings uses about 0.6–1.2M commands a month, which is above that cap. This estimate was not measured. Redis Cloud Free has no command quota, but it is limited to 30 MB, 30 connections, 1 IP allowlist rule and no backups ([Redis Cloud plans](https://redis.io/docs/latest/operate/rc/subscriptions/view-essentials-subscription/essentials-plan-details/)).

If PNC still wants the split, these code and config changes are needed. Each one comes from how Krosa works today.

**Redis over TLS.** `REDIS_URL` is a plain `redis://` URL in `docker-compose.prod.yml`. Managed Redis needs a `rediss://` URL (Upstash's example uses `tls: {}`). The worker builds its BullMQ connection with `new Redis(env.REDIS_URL, { maxRetriesPerRequest: null })` in `apps/worker/src/sync/sync.processor.ts`, and the API's queue and health clients need the same check. Also, BullMQ recommends turning off `enableOfflineQueue` on Queue instances, but keeping it on Workers ([BullMQ connections](https://docs.bullmq.io/guide/connections)).

**Fewer Redis commands.** The `Worker` options in the same file need much longer `drainDelay` and `stalledInterval` values than the defaults of 5 s and 30 s ([BullMQ API](https://api.docs.bullmq.io/interfaces/v5.WorkerOptions.html)). The research team estimates that 300 s and 300,000 ms would cut idle use to about 30–60K commands a month. Lengthen `WORKER_HEARTBEAT_INTERVAL_MS` too, because each heartbeat writes a Redis key. Trim finished jobs with `removeOnComplete` / `removeOnFail` so they fit in 30 MB.

**Let Neon sleep.** The worker's orphan sweep (`ORPHAN_SWEEP_INTERVAL_MS`) and `/api/v1/health/ready`, which checks the database, would keep Neon awake and use up its compute-hours. Point platform health checks at `/api/v1/health` and lengthen the sweep interval.

**Prisma connections.** Prisma 7 needs a pooled URL for the app and a direct URL for `prisma migrate deploy` and `ssrs_apply_term_defaults`, both set in `prisma.config.ts`. Add a higher `connect_timeout` so the first request after Neon wakes up does not fail.

**Pieces the platform replaces.** Caddy's `/api` routing has to be rebuilt in the platform's routing or in the web app's proxy. The Google service-account key currently mounted as a Docker secret has to move to the platform's secret store. The nightly `backup` container has to become a scheduled `pg_dump` to external storage, because no free database tier found includes real backups.

That is a fork of the deployment guide, built on four vendors' free tiers that can each change on their own. For a 6–12 month test, the cost is not worth it.

## Conclusion

The real constraint is not money or CPU. It is that free tiers do not last, and Oracle's quiet halving in 2026 proved it. That changes what matters most: a host that runs the existing compose file unchanged matters more than the most generous free tier, because it keeps any forced migration down to a single afternoon of copying backups. Seen that way, a single VM beats any split across PaaS and managed services. Keep the arm64 build working and the off-server backup current, and PNC can move between Oracle, AWS and a $12 VPS without touching code.

Some things remain unknown. Nobody has confirmed that Oracle or AWS sign-up works from Cambodia, or that A1 capacity is available in Singapore. Nobody has measured Krosa's real memory use or idle Redis traffic, and no data shows whether PNC's education mission will block the nonprofit credit programmes. Run `docker stats` during a sync before choosing a 2 GB VM, and treat the first week's Oracle attempt as the test that decides the plan.
